# 04 · 리스크 · 자본배분 · 운영 · 컴플라이언스

"무자비하게 번다"의 전제조건은 **죽지 않는 것**이다. 차익거래에서 파산은
보통 한 번의 미헷지 익스포저·거래소 인솔벤시·체결사고에서 온다. 이 문서는 그걸 막는다.

## 1. 리스크 프레임워크 (3중 방어선)

### 1선: 진입 게이트 (Brain)
- `net_bps > min_edge` 미달이면 진입 자체를 안 함.
- 피드 stale(>10s), 북 스프레드 >100bps, 북 mid 급변 >500bps, 교차거래소 mid 차 >300bps → 거부 (autotrading 기존 게이트 재사용).
- 심볼당/거래소당 포지션 캡, 전략간 순델타 합산 캡.

### 2선: 실시간 리스크 가드 (perpdex_assets 승격)
- 전 거래소 마진 집계, `marginFreePercent`:
  - **20% 경고** → 신규 진입 축소.
  - **10% 위험** → 신규 진입 중단 + 디레버리지 시작.
  - **5% 치명** → 해당 거래소 포지션 강제 평탄화.
- 일일 손실 한도(자본비례, 예: NAV의 1~2%) 도달 시 당일 신규 진입 정지.

### 3선: 전역 킬스위치 (사람 + 자동)
- 거래소 API 장애/출금정지/디페그 감지 → 해당 거래소 즉시 격리.
- 텔레그램 `/halt` 수동 킬스위치(기존 봇 명령 인프라 재사용).
- half-fill·leg 실패 누적 임계 초과 → 전체 일시정지(기존 `leg_failed`→`setPaused` 확장).

### 거래소(카운터파티) 리스크
- DEX 인솔벤시·해킹·러그 리스크 실재. **거래소당 자본 한도** 설정, 한 곳에 몰빵 금지.
- 정산 가능한 곳(출금 원활)과 그렇지 않은 곳 구분. 신규/소형 DEX는 캡 작게.
- 정기적으로 거래소 밖으로 이익 인출(콜드 스토리지).

## 2. 자본 배분

- **사이징**: 분수 켈리(1/4~1/2) 또는 고정 위험비율(트레이드당 NAV의 X%). 풀켈리 금지.
- **계층적 한도**: 트레이드당 → 심볼당 → 거래소당 → 전략당 → 전체.
- **기존 수치 자본비례 스케일링**: autotrading의 $20~$250/트레이드, $1,000/심볼, $100/일 손실은 소액 테스트 기준. NAV 증가 시 비율 유지하며 확대.
- **복리**: 실현익은 OI 캡(deposit×5) 내에서 재투자. 단, 정기적으로 원금+일부익은 인출해 시스템 리스크에서 분리.
- **준비금**: 마진콜 대비 거래소별 유휴 담보 버퍼 유지(가드의 디레버리지가 작동할 시간 확보).

## 3. 운영 (Ops)

- **관측성**: 단일 대시보드(PnL·포지션·전략별·활성신호) + 일일 리포트(기존 09:00 KST 확장).
- **감사 로그**: 모든 신호·결정·주문·체결 영속 기록(SQLite/Postgres). 분쟁·디버깅·세무.
- **시크릿 관리**: 거래 키는 read-only 키와 **분리**. perpdex_assets는 read-only 토큰만, Executor만 거래 권한. `.env` 커밋 금지(전 레포에 `.env.example`만 있는 패턴 유지). 키는 KMS/Secrets Manager로 이관 권장.
- **배포**: 신호/실행 분리. PM2/systemd(기존) → 점진 컨테이너화. 지연민감 leg는 거래소 리전 근처.
- **장애 대응**: 프로세스 죽으면 자동재시작하되, **재시작 시 미체결/고아 포지션 복구 루틴** 필수(차익 leg가 한쪽만 살아있는 상태 감지·평탄화).
- **테스트**: 페이퍼 리플레이(과거 신호 로그)로 전략 검증 → 소액 라이브 → 스케일. 신규 전략 직행 금지.

## 4. 핵심 안전 수정사항 (실거래 전 반드시)

1. **autotrading 라이브 게이트 버그**: 현재 `TRADING_MODE=live`만 검사하고 `TRADING_ENABLED`는 로깅만 한다. → *두 플래그 AND* 를 Executor 인스턴스화 시점에서 하드 게이트로 강제.
2. **고아 leg 복구**: 동시체결 중 한 leg만 성공 시 자동 평탄화 + 정지. 재시작 시 포지션 재대조.
3. **부분체결 사이징**: cost oracle의 fillRatio를 Allocator가 반영해 미체결분 자동 축소(현재 신호는 top-of-book만 봄).
4. **stale 데이터 게이팅 강화**: 알람용 10s는 실행엔 느슨. 실행 leg는 1~2s로 타이트하게.

## 5. 컴플라이언스 · 합법성 (반드시 읽을 것)

이 시스템은 **합법적 엣지만** 추구한다. 다음은 명시적으로 **하지 않는다**:
- 시장조작(스푸핑, 레이어링, 워시트레이딩, 펌프앤덤프).
- 타인 주문 유발/선행매매를 노린 조작.
- 내부정보·비공개정보 이용.
- 탐지회피·규제우회 목적의 난독화.

**추구하는 것**: 차익거래(arbitrage), 마켓메이킹, 펀딩 캐리, 실행속도 우위 — 모두 시장에 유동성을 공급하고 가격을 정렬하는 합법적 활동.

**규제 체크리스트 (특히 A5 김치 프리미엄)**:
- 한국 거주자의 해외 거래소 이용·외화송금·자금세탁방지(특금법) 규제 확인.
- 거래소 KYC/약관상 봇·API 자동매매 허용 여부 확인(일부 거래소는 제한).
- 세무: 모든 체결 기록 보관, 양도소득·기타소득 신고 의무 확인.
- 본인 자금만 운용. **타인 자금을 받아 운용하면 투자일임/집합투자 규제 대상** → 별도 인가 필요. 초기엔 자기자본만.

> 요약: 기술적으로 공격적이되 법적으로는 보수적으로. 한 번의 규제·법률 사고가
> 수년 수익을 날린다. 불확실하면 실행 전 한국 변호사·세무사 자문.
